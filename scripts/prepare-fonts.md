# Preparing the Montserrat files

Documentation, **not an executable script**: the procedure needs `python3` + `fonttools`, which
neither CI nor the Dockerfile installs, plus a one-off download from Google Fonts. It is run by
hand, locally, and **only** when the font version is bumped. The resulting files are committed.

The site's typeface is **Montserrat**, and it is used across **the whole page** — body copy and
headings alike — not only in titles. There is no second family.

`next/font/local` **does not subset anything**: it serves the file it is given. The full variable
Montserrat is 745 KB as TTF, so what reaches the browser has to be a subset prepared beforehand.
Hence this document.

The project **does not use `next/font/google`**: that would make every build (CI and Vercel) depend
on the network and on Google answering, and it ends up self-hosting the file anyway. The file is
downloaded once, by hand, and versioned. The cost is this manual procedure.

## 2. Where each file came from

A one-off download, authorised by the site owner. It is the **only** time the project touches the
network for this: neither the build nor CI ever does it again.

### 2.1 The `.woff2` that is served

1. Request the Google Fonts CSS **with a modern User-Agent** (with an old one Google returns TTF
   instead of WOFF2):

   ```bash
   curl -s -A "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120 Safari/537.36" \
     "https://fonts.googleapis.com/css2?family=Montserrat:wght@100..900&display=swap"
   ```

2. The response has one block per subset. Take the `src: url(...)` from the block commented
   `/* latin */` — not `latin-ext`, not `cyrillic`, not `vietnamese` — and download that URL to
   `src/lib/assets/fonts/Montserrat-Variable-latin.woff2`.

   The `fonts.gstatic.com` URL carries a hash that changes with every font version, so it is
   **not pinned here**: read it from the CSS at the moment of regenerating. `latin-ext` would add
   weight for characters this site does not use.

### 2.2 The `.ttf` and the licence

From the official `google/fonts` repository, directory `ofl/montserrat/`:

| Source | Destination |
|---|---|
| `ofl/montserrat/Montserrat[wght].ttf` | `src/lib/assets/fonts/Montserrat-Variable.ttf` |
| `ofl/montserrat/OFL.txt` | `src/lib/assets/fonts/OFL.txt` |

`OFL.txt` is copied **verbatim**: a licence text is neither rewritten nor summarised.

## 3. Regenerating or re-subsetting

Requires `python3` and `fonttools` (`pip install fonttools brotli`).

If the subset Google serves stops being enough (for instance if a character it does not carry were
needed), generate one from the variable TTF, which is already in the repository and **does not need
downloading again**:

```bash
pyftsubset src/lib/assets/fonts/Montserrat-Variable.ttf \
  --unicodes="U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+02C6,U+02DA,U+02DC,U+0304,U+0308,U+0329,U+2000-206F,U+2074,U+20AC,U+2122,U+2191,U+2193,U+2212,U+2215,U+FEFF,U+FFFD" \
  --layout-features="kern,liga,calt,tnum" \
  --flavor=woff2 \
  --output-file=src/lib/assets/fonts/Montserrat-Variable-latin.woff2
```

Two warnings about this:

- Google's `latin` subset is **not byte for byte** what this `--unicodes` list produces. On
  regeneration the file changes size and md5 even when the font version is the same. That is
  expected and not an error.
- `pyftsubset` keeps the `wght` axis as long as neither `--instancer` nor `--drop-tables=fvar` is
  passed. If the resulting file stops being variable, the site loses every weight but one.

Afterwards, **always**:

1. `npm run test` — `src/lib/fonts.test.ts` reads the real files from disk and checks the format
   signature, the weight budget (110 KB), the latin-subset ceiling (60 KB) and the presence of
   `OFL.txt`.
2. Rename the file **only** if the path in `src/lib/fonts.ts` is changed as well: the name
   `Montserrat-Variable-latin.woff2` is written in three places (the `src` of the `localFont` call,
   the test, and this document).

## 4. What the `.ttf` is for

**satori**, the renderer behind `next/og`, **cannot read WOFF2**: it needs a TTF or OTF buffer.
That is why `Montserrat-Variable.ttf` is in the repository even though it is **never served to the
browser** and is not referenced by `src/lib/fonts.ts`. The OG image reads it with `readFile`.

It is the complete set (2 747 glyphs) and variable. If its weight in the server bundle ever becomes
a problem, it can be instanced to a fixed weight — still without downloading anything — with:

```bash
fonttools varLib.instancer src/lib/assets/fonts/Montserrat-Variable.ttf wght=600 \
  -o src/lib/assets/fonts/Montserrat-SemiBold.ttf
```

This has not been done: which weights the OG card needs is not settled yet.

## 5. Metrics and a fallback without CLS

`src/lib/fonts.ts` declares `adjustFontFallback: "Arial"`. For a **local** font Next uses no
precomputed table: it runs the file through `fontkit` and computes the fallback `@font-face` from
its real metrics, so the numbers recompute themselves when the font changes.

Metrics of the committed file (they match Next's capsize table exactly):

| | value |
|---|---|
| `ascent` | 968 |
| `descent` | −251 |
| `lineGap` | 0 |
| `unitsPerEm` | 1000 |
| `xWidthAvg` | 503 (0.503 em) |

And this is what Next emits from them for the `local(Arial)` fallback:

```
size-adjust: 110.19%;  ascent-override: 87.85%;  descent-override: 22.78%;  line-gap-override: 0.00%;
```

**Known caveat:** `fontkit` measures the widths of the file's default instance, which here is
`wght=100` (section 1). For body copy, which renders at 400, the ideal `size-adjust` would be
`113.90%`. The difference is about 3 % of average width and `next/font/local` offers no option to
tune it; correcting it would require `adjustFontFallback: false` and a hand-written fallback
`@font-face` in `globals.css`. It is not worth it.

## 6. Licence

Montserrat is distributed under the **SIL Open Font License 1.1**, which **requires the licence
text to be distributed alongside the font files**.

`src/lib/assets/fonts/OFL.txt` is that copy, verbatim, taken from `ofl/montserrat/` in
`google/fonts`. It **must always travel with the `.woff2`/`.ttf`**: it is not deleted, not moved to
another directory and not replaced by a link. `src/lib/fonts.test.ts` fails if it disappears or if
it stops containing the OFL 1.1 text.

The OFL does not require showing the licence in the site's interface, only distributing it with the
files, which is what the repository does.

## 7. Contracts with the code

| Contract | Value |
|---|---|
| Export of `src/lib/fonts.ts` | `sans` (a role name, neutral to typeface changes) |
| CSS variable it declares | `--font-montserrat` |
| Who applies the class | `src/app/layout.tsx`: `<html className={sans.variable}>` |
| Who consumes it | `src/app/globals.css`: `--font-sans: var(--font-montserrat, ui-sans-serif), …` |
| Declared weight range | `100 900` (the file's real axis) |
| `display` | `swap` |

There are **three** links in the chain, not two, and the middle one is the one that gets forgotten.
The `import { sans }` in `layout.tsx` is what puts this module into the compiled graph: without it
`next/font/local` never runs — no `@font-face`, no `.woff2` in `.next/static/media/`, and nothing
declares `--font-montserrat` — and `npm run build` still succeeds. Any rewrite of the layout has to
keep both the import and the class.

Neither breakage throws an error, so there are two safety nets:

- `src/lib/fonts.test.ts`, block `font wiring`. It reads the three files as text and derives the
  variable name from `fonts.ts` instead of hard-coding it, so it survives the next typeface change
  and still detects drift.
- The fallback **inside** the `var()`. If `--font-montserrat` did not exist, the substitution fails
  and invalidates the whole value of `--font-sans`, reserve list included: `<body>` would inherit
  the initial `font-family`, which in every browser is a serif. With the second argument the
  breakage degrades to the system stack, which is what this table promises.

A quick manual check after any font change:

```bash
npm run build && find .next -iname "*.woff2"
```
